# 多设备登录差异 & 上传同步失败：排查与修复

适用版本：构建 `2026-11-15.1` 及以上。

## 一、结论速览

| 现象 | 根本原因 | 归属 | 修复 |
|---|---|---|---|
| 录完显示「同步失败」 | `supabase/schema.sql` 的 `stories` 列级 INSERT 授权**漏了主键 `id`**，但客户端写入时显式传了 `id`，Postgres 以 42501 拒绝整条 INSERT | 服务端权限，确定性缺陷 | 执行 `supabase/patch-grants.sql`；schema.sql 已修 |
| 华为 WiFi 下用不了、移动数据正常 | ① 外部字体 CSS 是**渲染阻塞资源**，弱网/被拦时首屏长时间卡住；② 该 WiFi 对 `supabase.co` 的 DNS/IPv6/路由异常 | 前端 + 网络 | 字体改非阻塞加载；诊断面板定位网络；改 DNS/关 IPv6 |
| 苹果设备无法登录 | 待区分：账号未建好 / iOS 独立 PWA 的 Service Worker 缓存了旧 `config.js`（空配置→仅本机模式）/ 网络被拦 / iOS 存储受限 | 多因素 | SW 改网络优先、config.js 不缓存、iOS 存储兜底、A/B 矩阵定位 |

> 说明：`https://ygvaqsjgisitmxjaezvp.supabase.co` 的服务端已实测可达——Auth 服务返回 GoTrue 版本信息，REST 返回正常的权限错误，Storage 端点正常响应。项目本身没有宕机。本机用不同 DNS 解析该域名均得到 Cloudflare 地址，但本机直连被代理 502，这类「同域名不同网络路径结果不同」正是问题的典型特征。

## 二、必须你执行的两步（顺序不要反）

### 第 1 步：补数据库权限（约 1 分钟）

1. Supabase → `SQL Editor` → `New query`。
2. 打开 `supabase/patch-grants.sql`，全选复制粘贴 → **Run**。
3. 结果区应输出一行 `stories_id_insert_ok = true`、`stories_cipher_insert_ok = true`、`states_updated_at_ok = true`。
4. 这一步只改权限，不动任何数据，可重复执行。

**不执行这一步，上传仍然会失败**，因为「音频传上去了、故事记录写不进去」。

### 第 2 步：让三台设备拿到新代码

旧版 Service Worker 是「缓存优先」，iOS 独立 PWA 和华为浏览器可能长期用旧的 `config.js`（空值 → 仅本机模式 → 看起来像无法登录）。新版已改为网络优先，但设备需要先更新一次：

- 每台设备打开 `https://czj0311.github.io/bedtime-stories/`，**刷新两次**（第一次更新缓存，第二次用新代码）。
- 若仍是旧界面：点右上角齿轮 → **网络诊断** → **强制更新缓存**，会自动清缓存并重载。
- 诊断结果第一行 `构建：2026-11-15.1` 即为新版；显示「未知」说明还是旧缓存页面。

## 三、A/B 对比矩阵（用来区分「账号问题」还是「设备/网络问题」）

请在下列组合里各点一次「网络诊断」，把结果复制出来。重点是**同一账号换网络**、**同一网络换账号**两组对照。

| 编号 | 设备 | 网络 | 用哪个账号 | 想验证什么 |
|---|---|---|---|---|
| A1 | 你的小米 14 | WiFi | 你的账号 | 基准（已知可登录） |
| A2 | 你的小米 14 | 移动数据 | 你的账号 | 网络是否影响你的账号 |
| B1 | 你的小米 14 | WiFi | **她的账号** | 若失败 = 账号本身问题（未创建/未确认/密码错），与苹果设备无关 |
| B2 | 她的苹果设备 | WiFi | **你的账号** | 若成功 = 苹果硬件/浏览器没问题，问题在她的账号或她的网络 |
| C1 | 她的苹果设备 | WiFi | 她的账号 | 复现原始故障 |
| C2 | 她的苹果设备 | 移动数据 | 她的账号 | 若成功 = 她的 WiFi 拦截了 supabase.co |
| D1 | 华为设备 | WiFi | 你的账号 | 复现 WiFi 故障 |
| D2 | 华为设备 | 移动数据 | 你的账号 | 基准对照 |

判读规则：

- **B1 失败、B2 成功** → 她的账号没建好。去 `Authentication → Users` 检查：账号是否存在、是否 `Confirmed`（手动建号时勾 **Auto Confirm User**）、密码是否正确。必要时删掉重建。
- **C1 失败、C2 成功** → 纯网络问题，见第五节。
- **任何一格显示 `config.js：URL=(空)` 或「构建：未知」** → 旧 SW 缓存，先做第 2 步。
- **三个云端端点都显示 HTTP 状态码（哪怕是 401/42501）** → 网络通；只看「账号 / 会话 JWT 角色 / 数据库读取」三行。
- **出现 `✗ 无法连接`** → 当前网络拦截，换网络或改 DNS。

## 四、上传同步失败：链路与定位

新版本把失败拆成可区分的四个环节，错误信息会显示在齿轮弹窗和「同步失败」角标上：

| 编号 | 环节 | 典型原因 |
|---|---|---|
| ① | 本机加密 | 设备缺 WebCrypto / 非 HTTPS / 录音 Blob 损坏 |
| ② | 音频上传到 Storage | 网络断开、桶策略不允许、文件过大 |
| ③ | 故事记录写入数据库 | **权限未补（42501）**、RLS 成员关系异常 |
| ④ | 对方接收 Realtime | 订阅未建立、对方未解锁密钥 |

在齿轮弹窗点 **测试上传**，会跑一组可逆写入探针：上传一个测试文件再删除、`stories` 插一条测试行再删除。输出里：

- `[stories INSERT] ✓ 成功` → 权限已补好，同步应该恢复。
- `[stories INSERT] ✗ permission denied` → 补丁 SQL 没执行成功，回第 1 步。
- `[Storage 上传] ✗` → 桶或存储策略问题，把完整报错发我。

补传：齿轮弹窗 → **重试同步**（会跳过网络失败退避立即重试）。

## 五、WiFi 连不上云端的处理顺序

1. **换 DNS**：手机 `设置 → WLAN → 当前网络 → 修改网络/配置 DNS → 手动`，填 `223.5.5.5` 与 `119.29.29.29`；或直接在路由器里改上游 DNS。
2. **关掉该 WiFi 的 IPv6**（或关闭手机的 IPv6）：DNS 会同时返回 AAAA 记录，部分宽带/校园网 IPv6 路由不通，浏览器回退很慢甚至超时；移动数据通常 IPv6 正常，这正好解释「流量能用、WiFi 不能」。
3. **检查是否需要网页认证**：校园网、酒店、商场 WiFi 常要先在浏览器里点一次「上网认证」，未认证时所有外网请求被拦。
4. **排除路由器拦截**：家长控制、企业网关、去广告插件可能拦 `supabase.co`。用手机流量开热点给另一台设备连，若正常即可确认是路由器/宽带侧。
5. **苹果设备额外检查**：`设置 → 无线局域网 → 当前网络 → 关闭「私有 Wi-Fi 地址」`后再试；并确认 Safari 未开启「阻止跨站跟踪」影响站点数据（同源不受影响，但独立 PWA 的站点数据可能被清）。
